Fix #1: OrgId Length Mismatch HIGH

Problem

The script was using 18-character OrgIds in test pages, but the ECV2 widget expects 15-character OrgIds. This caused 400 Bad Request errors on SSE connection and polling endpoints.

Test Case 1.1: Verify OrgId Truncation

  1. Run the script and let it create a test page
  2. Open the generated test-enhanced-chat-*.html file
  3. Find the embeddedservice_bootstrap.init() call
  4. Verify the first parameter (OrgId) is exactly 15 characters

Expected: '00Dfi700008S6gz' (15 chars)

Not: '00Dfi700008S6gzEAC' (18 chars)

Test Case 1.2: Widget Functionality

  1. Open test page in browser (via correct domain)
  2. Wait for chat button to appear
  3. Click button and send a test message
  4. Check browser console for errors

Expected: No 400 errors on /sse or /poll endpoints

Fix #4: Clone is SSH-Only HIGH

Problem

Script only tried SSH for cloning enhanced-chat repo. Failed for users without SSH keys configured.

Test Case 4.1: Clone Without SSH Keys

  1. Remove or rename your SSH key: mv ~/.ssh/id_rsa ~/.ssh/id_rsa.backup
  2. Delete enhanced-chat repo if exists: rm -rf ~/enhanced-chat
  3. Run script and choose to create GitHub Pages test page
  4. Observe clone attempt
  5. Restore SSH key: mv ~/.ssh/id_rsa.backup ~/.ssh/id_rsa

Expected: Script tries SSH first, falls back to HTTPS, successfully clones

Output should show: "SSH failed, trying HTTPS..." then "✅ Cloned enhanced-chat repo"

Test Case 4.2: Clone Fallback Order

Script should try in this order:

  1. SSH: git@git.soma.salesforce.com:embedded-service-for-web/enhanced-chat.git
  2. HTTPS: https://git.soma.salesforce.com/embedded-service-for-web/enhanced-chat.git
  3. Manual instructions if both fail
